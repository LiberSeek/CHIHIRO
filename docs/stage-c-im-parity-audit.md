## Remaining acceptance order

1. Use a real account to manually verify image preview media URLs, CORS-sensitive image display, forwarding to live contacts, face insertion into live messages, and final pixels. The mock browser pass proves the migrated UI contracts, not NapCat's live media transport.
2. Keep real customer targets out of these checks; use an isolated account/chat when validating live send and forward behavior.
3. Docker image validation remains pending until the local Docker daemon is available.

## Validation status

Current automated validation passes with the project runtime: `npm run test --workspace frontend`, `npm run typecheck --workspace frontend -- --pretty false`, `npm run build --workspace frontend`, `node frontend/src/modules/im/native/verify-source.mjs`, and `npm run qa:native-im --workspace frontend -- --interactions`. The interaction QA loads the real `frontend/dist` in Chromium with a local mock Runtime/OneBot fixture and verifies empty composer behavior, explicit multiline input, image viewer bounds, viewer toolbar avatar/gutter, zoom/close, emoji popup layout/background, forward card backgrounds in both themes, and zero browser errors. Docker image validation later passed on the Colima Docker context with `docker build --file Dockerfile --tag chihiro:0.1.0-check .`; a temporary container served `/api/status`, and the temporary image was removed after validation. Release manifest, backup/restore simulation, and Compose expansion are covered by `make manifest-check`, `make compose-config`, and `make compose-config-external`.
