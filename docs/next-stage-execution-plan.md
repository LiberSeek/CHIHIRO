# 千寻下一阶段：Bot 与 Agent

状态：进行中。工作台入口、QQ 登录、多账号 IM 已在 `/`。本阶段开发 **Bot（会话接待）** 和 **Agent（操作员工作台）**。

产品口径：[product.md](product.md) 第 3 节。工程契约：[development.md](development.md) 第 4–7 节。

## 目标

让人、助手、Bot 在同一套 IM 里同时在场，且不能互扮。

```text
客户消息 ──► 会话
              ├─ 人直接回     → 发给客户
              ├─ 人问助手     → 内部通道，不进客户历史
              └─ 策略触发 Bot → 候选草稿 → 审批或自动 → 统一发送出口
操作员任务 ──► 工作台 Agent  → 同一套工具与发送出口
```

不做：营销群发、画像评分、多群情报报告、把工作台再收成「稳定底座」清单。

## Bot：会话接待

每个客户会话独立策略。输入框右上角开面板；托管后状态、依据、候选在输入框上方。保留正常输入。

| 模式 | 产品名 | 现状（代码） | 要做成 |
|---|---|---|---|
| 人工 | 不主动插嘴 | 未托管 | 关托管即停该会话的自动生成，不影响其它会话和 Agent |
| 辅助 | 操作员调用才建议 | `ask` + `/agent/ask` | 「问助手」与「发给客户」两个动作；内部指示不伪装成客户消息 |
| 审核 | 触发后出候选等确认 | `auto`（现按链接/图/@全体拦截） | 改为会话策略；候选可编辑、过期、审批 |
| 自动 | 预划定范围内执行 | `always` | 越界待处理；发送走 Outbox，禁止假成功 |

交付：

1. 会话策略：模式、触发、时段、知识范围、动作权限、版本。替换只按媒体类型拦截的 `ask/auto/always`。
2. 问助手：独立通道；结果是建议，不是已发送。
3. 草稿：绑定会话版本；新消息、人工开口、人工发信、改策略使旧草稿失效。
4. 审批与接管：条件领取，重复确认不连发；人说话即接管。
5. 发送出口：proposal / attempt / receipt；`accepted` 不是已读；超时是 `unknown`。
6. 生命周期：AstrBot 按 ChatUI、托管会话、计划任务的运行需求拉起；单个 Bot 开关不能停掉其它任务。

## Agent：操作员工作台

工作台是操作员对 Agent，不是客户会话。入口 `/im?tab=workbench`。

交付：

1. 对话仍是 AI 对话；业务任务、客户会话、Agent run 明确映射，不混用 sessionId。
2. 千寻工具：读账号/会话/历史、提草稿、受控发送。作用域来自服务端运行记录，不信模型自报账号。
3. 同一会话里 AstrBot 原生 QQ 适配器不得与千寻 Bot 同时自动回复。
4. Dashboard 只作高级设置；常用策略进千寻表单。
5. 跨账号任务展示作用账号范围，不随左栏当前账号悄悄改执行目标。

MCP 只做工具访问。当前 `/mcp` 若仍是说明 Markdown，不能当成 Streamable HTTP 端点。

## 顺序

```text
1. 通道分开：问助手 ≠ 发给客户；禁止模拟客户事件
2. 会话策略 + 草稿版本 + 审批领取
3. 统一发送出口（去掉 fakeOk / 回执前标已回复）
4. Agent 工具接到同一出口；运行租约替代「一个 Bot 开关关进程」
5. 审核/自动模式按策略触发，影子运行后再扩大
```

合入口径：相关测试、构建、`git diff --check`。发信路径禁止虚构成功。
