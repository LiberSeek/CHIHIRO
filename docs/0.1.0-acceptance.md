# 千寻 0.1.0 基础可用版验收清单

状态：进行中。基线：`0.0.2`。目标：把统一前端从可用原型推进到稳定的日常 IM + Agent 工作台。

## 产品完成定义

0.1.0 不追求完整营销获客、群发、画像和报告。它只回答一个更基础的问题：千寻能否作为一个稳定的 AI IM 工作台使用。

用户应该能在一个入口完成 QQ 登录、切账号、看消息、看联系人、打开工作台、与 Agent 对话、进入必要设置，并且刷新、切换、退出、重登后不丢状态、不串账号、不出现明显 UI 断裂。

## 必须通过

### 账号与登录

- [x] 空账号时只显示启动页，不闪消息 / 联系人列表。
- [ ] 添加 QQ 账号显示客户端下拉和启动按钮。
- [x] 登录中、取消登录、退出账号都有明确加载状态。
- [ ] 退出确认支持 Esc 关闭，执行中不能误关。
- [x] 第二个 QQ 账号登录流程不会复用上一个账号的“已登录”信息。
- [ ] 账号栏显示头像、在线状态、Bot 角标和未读数。
- [ ] NapCat 设置只出现在 QQ 账号右键菜单中。

### IM 基础体验

- [ ] 消息列表不会因 runtime polling 或账号切换持续抖动。
- [ ] 联系人列表不会因 runtime polling 或账号切换持续抖动。
- [ ] 消息 / 联系人 / 工作台列表边框、背景、顶部高度一致。
- [ ] 联系人单击显示详情，双击回到消息并打开会话。
- [ ] 会话返回后显示“选择 对话/任务 开始”。
- [ ] 图片预览、转发窗口、表情弹窗、输入框返回行为对齐当前 Stapxs 定制版。
- [ ] IM 弹层、信息栏、表情弹窗不出现透明背景穿透。
- [ ] 全局 toast 在页面上方居中，不挤在列表区域。

### 多账号与状态归属

- [ ] A 账号和 B 账号拥有相同 peerId 时，历史、草稿、未读、附件不串。
- [x] A 请求未返回时切 B，迟到响应不能覆盖 B。
- [x] 账号切换时旧账号未读不会写到新账号。
- [ ] 新消息只更新所属账号的未读。
- [ ] 移除一个账号不会清理其它账号状态。
- [x] 切换账号后路由和右侧聊天区指向一致。

### Agent 工作台

- [ ] 工作台侧栏位于列表工作区，Agent 聊天区位于 IM 右侧区域。
- [x] 点击 Agent 会话后路由停留在统一工作台 `/im?tab=workbench&agent=:conversationId`；旧 `/agent/:conversationId` 仅作为兼容入口并归一到工作台。
- [x] 切回消息 / 联系人或普通 IM 会话后路由恢复为 `/im` 对应状态。
- [x] Agent 返回后隐藏聊天区，显示“选择 对话/任务 开始”。
- [ ] 默认模型选择位于输入框区域，顶部为返回按钮和更多菜单。
- [ ] AstrBot 设置在 Agent 顶部更多菜单最后一项，完整 Dashboard 只作为高级设置入口。

### 构建与发布

- [x] `npm run typecheck --workspace frontend -- --pretty false` 通过。
- [x] `npm run test --workspace frontend` 通过。
- [x] `npm run build --workspace frontend` 通过。
- [ ] Docker 镜像可构建。
- [ ] `deploy/` 说明标准 Compose 和外部 NapCat 两种运行方式。

## 当前优先任务

1. 多账号状态归属和异步请求保护。
2. IM 与 Stapxs 定制版交互 parity。
3. Agent ChatUI 原生模块化收尾。
4. 会话助手最小闭环。
5. Docker 运行模式文档与健康检查。

## 暂缓

- 营销获客自动执行。
- 大规模群发。
- 客户画像与购买意图评分。
- 多群情报报告。

这些能力依赖稳定的消息采集、会话策略、AgentRun、ReplyProposal 和 Outbox。0.1.0 先把产品底座做好。
