# 千寻产品模型（修订）

千寻不是「三个后台服务 + 一个反代」。  
它是一个 **共用一套 IM 前端的工作台**：多客户端、多账号；**正常聊天为主，Bot 自动回复为辅**。

左侧竖栏用 **客户端/账号 icon** 切换当前在看哪一路；中间永远是同一套会话列表 + 聊天区。  
添加账号时用 **下拉选择客户端类型**（对齐 AstrBot 已支持的消息平台），Runtime 再按类型拉起对应后端（QQ 才是 NTQQ `--no-sandbox`）。

---

## 1. NapCat / NTQQ：你的理解基本正确

Mac 上 NapCat **Shell** 必须拉起官方 **NTQQ**（QQ.app），并带 `--no-sandbox`。  
这是基座，不是给用户看的客户端。

纠正两点：

1. **用户不应自己执行** `QQ --no-sandbox`。那是千寻 Runtime 的内部动作。  
2. **一个 QQ 进程 ≈ 一个账号。** 同号不能同时开原生 QQ 和 NapCat。真·同时多开在 Mac 沙箱下很难（共用 `com.tencent.qq` 容器）。第一版「多账号」定义为：  
   - 工作台内账号列表  
   - 已登录过的号 **快速登录、免再扫码**（后端未退出则保持会话）  
   - 切换账号由千寻拉起/切换 Shell  
   - 同时在线多个号：后置（优先 Linux/独立数据目录方案）

### 添加账号时：先选客户端，再登录

下拉选项对齐 AstrBot 官方消息平台（社区适配器后置）：

| 客户端 | 登录形态 | Runtime 动作 |
|---|---|---|
| **QQ / OneBot v11（NapCat）** | 工作台内二维码 / 快速登录 | spawn NTQQ `--no-sandbox` |
| Telegram | Bot Token | 起对应适配器，不拉 QQ |
| 飞书 / 钉钉 / 企微 | 开放平台凭证 | 同上 |
| Discord / Slack / LINE / KOOK 等 | 各平台 token | 同上 |
| 微信公众号 | 公众号配置 | 同上 |

只有选了 QQ/NapCat，才会 spawn NTQQ。其它客户端走 AstrBot 适配器或独立连接器。

### QQ 账号的目标启动流（对用户）

```text
打开千寻
    │
    ├─ 左侧「+」→ 下拉选择「QQ」
    ├─ Runtime 拉起 NTQQ --no-sandbox（后台，用户看不见终端）
    ├─ 未登录 → 工作台内展示二维码
    ├─ 扫码成功 → 该账号 icon 出现在左栏，进入共用 IM
    └─ 后端未退出 → 该号保持登录；下次点 icon 直接看会话
```

不再出现「先开终端再开网页」的开发者流程（那只是当前脚手架现状）。

## 2. AstrBot：按「应用 / 插件」而不是常驻底座

你的理解正确：AstrBot 是 **LLM 自动回复与事件调度**，监听某人/某群/某事件后回复。

产品里它是 **可安装、可开关的应用**，不是一开机就占资源的总后台。

```text
用户在千寻「应用」里启用某个 AstrBot 应用
    → 千寻才拉起 AstrBot 进程（或容器）
    → 接到当前账号的 OneBot
    → 关闭应用 / 退出千寻后端 → 停掉 AstrBot
```

和 IM 的关系：

- IM（Stapxs）：人在工作台里聊天  
- AstrBot：后台按规则托管；会话级可「接管 / 托管」

## 3. 千寻要做成什么样

**一套前端，多路客户端。** 交互对标 QQ 桌面，而不是 AstrBot 运维台。

```text
┌──────┬────────────┬─────────────────────┐
│ 左栏  │ 会话列表    │ 聊天区               │
│ icon │            │                     │
│ QQ   │  共用 IM UI │  正常聊天（主）       │
│ 飞书  │            │  Bot 托管开关（辅）   │
│ TG   │            │                     │
│  +   │            │                     │
└──────┴────────────┴─────────────────────┘
   ↑ 点 icon = 切换「当前客户端账号」
   中间 UI 不变，只换数据源
```

- **主路径：** 人在工作台里当普通 IM 用（读历史、发消息、切会话）。  
- **辅路径：** 当前账号可打开 Bot（AstrBot 应用）：按人/群/事件自动回复；关闭即停进程。  
- **左栏：** 每个已登录账号一枚 icon（带客户端角标）；`+` 下拉选客户端再登录。

```text
Chihiro Runtime
├── 账号会话表（client_type + account_id + 登录态）
├── QQ 账号 → NTQQ+NapCat + OneBot
├── 其它账号 → 对应适配器（AstrBot platform adapter）
└── Bot 应用 → 仅在用户开启时挂到「当前账号」
```

二次开发：直接改 `vendor/stapxs` 作为 IM 壳；NapCat 只管 QQ 协议；AstrBot 提供多平台适配与 Bot 调度。Agent 读仓库根目录 [AGENTS.md](../AGENTS.md)。

## 4. 和当前脚手架的差距

| 现状 | 目标 |
|---|---|
| 人手 `QQ --no-sandbox` | 千寻 Runtime 拉起 |
| 终端/文件二维码 | 工作台登录页展示二维码 |
| 单账号手工连 Stapxs | 账号会话由 Runtime 维持 |
| AstrBot 独立常驻 | 应用开关才运行 |
| Gateway 只反代 | Runtime + 工作台壳 |

下一步工程：`apps/runtime`（客户端类型、进程、二维码、账号会话）+ 左栏账号切换；第一版先做 **QQ 一条链路**，下拉框把其它客户端占位出来。
